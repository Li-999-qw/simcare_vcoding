## 页面操作

- 接诊：左侧患者对话；右侧主诉/现病史、查体、辅助检查、诊断、依据。问诊回复期间也可书写病历、申请及查看检查。
- 查体、分类检查申请、报告查看和上级请教均通过弹窗操作。检查跨分类多选；报告先预览再导入独立栏目，重复导入去重。尚未接入的报告入口标为不可用。
- 处置与交接：左侧输入指令，右侧保留指令卡片及交接计划。当前仅记录指令，不声称下级医师已执行。
- 查房与出院：显示各自病历字段，不再把所有阶段的输入框堆在同一页。
- 点击底部按钮顺序推进，顶部可回看已完成场景。新版本在离开场景时保存病历和报告快照；回看为只读。旧版本演练无历史快照时明确标为现存病历，不伪造历史。
- 右上角“流程”按钮展开浮窗，收起后让出工作台空间；左侧患者情景图随阶段切换，点击放大。四幅图片由内置图像工具生成，仅作场景示意，素材与提示词保存在 `public/assets/`。
- 病历输入自动保存，提交需核对确认，提交后锁定。自主练习提供独立复盘对话；考试不显示教学提示和答案。

## 启动

在正常已登录的 Windows 用户环境中运行 `python rehearsal/server.py`，打开 http://127.0.0.1:8765 。需要已安装并通过 `codex login` 登录的 Codex CLI；不用填写、读取或复制API密钥。本程序通过官方 `codex app-server` 生成角色回复，消耗当前Codex账号额度。当前使用 `gpt-6-astra`、低推理强度和默认服务等级。

连接在服务启动时预热。同一演练、同一角色及同一阶段复用临时对话线程，最多连续六轮后按当前事实和历史重建；最多保留八个线程。学生、角色、阶段、练习/考试模式及病例版本分别隔离。回复按已到达文字逐步显示，300毫秒轮询；来源范围校验通过前不展示正文，最终有效回复才写入正式记录。异常时清除临时文字。生成期间可继续书写病历。

服务只监听本机。使用 `--port 端口号` 更换端口。会话保存在项目 `tmp/rehearsal-sessions.json`，同一浏览器标签可在重启服务后恢复；请导出重要记录。此文件不纳入Git。无后台定时任务。

## 边界

- 这是局部病例和真实模型的对话联调，不是完整临床模拟器或正式考试系统。
- 病例事实摘自 `../build_case_pdf.py` 的专家审核版v1.0，仍待临床专家审核；`case.py`是联调子集，不是病例主文件。
- 角色策略依据“对话智能体”任务的 `病例角色对话_设计约定v0.2.md`。患者与上级上下文分别构造，不将完整病历或未来病例直接传给前端。
- 患者可依据问题披露病史；上级仅获得已实际披露的回复、已打开报告及本阶段教学参考。角色回答仍需专家评估，不将提示约束宣称为可靠的医学审核。
- 五场景顺序推进。进入病房按预设病例加载交接，不依学生处理模拟疗效；口述或填写计划不视作已经实施。
- 检查即时返回，标注原病例时间，不评价等待时效。检查图像为原病例教学合成示意，并非设备原始采集资料；患者情景图不是检查证据。
- 练习提供形成性点评，无数字评分。考试测试不提供教学答案；提交后锁定记录，等待教师发布（尚无教师发布后台）。
- 语音暂缓。后端保留的 Windows 语音试验不代表已经通过语音验收，当前前端不调用这些接口。
- Codex子进程使用只读沙箱，禁用工具、插件、应用、联网搜索等能力；不改用户全局配置。使用独立HTTP provider配置沿用Codex登录，避免本机WebSocket反复重连。学生输入经stdin传入，绝不拼接为shell命令。

## 验证

`python -m unittest discover -s rehearsal -p 'test_*.py' -v` 检查角色信息边界、申请与阅读分离、独立字段、导入去重、旧记录兼容、场景快照、并行书写与提交锁定等。

浏览器联调使用独立演练，不覆盖用户作答。当前验收限文字：患者真实回复、上级弹窗、分类申请、预览导入、场景推进、回看、提交和复盘。24 项自动测试通过，包含增量文字显示、失败清理、事实范围校验，以及线程复用、隔离和轮换。

报告与反馈更新后共32项自动测试通过，新增阳性导入、空阳性处理、数据时序、历史证据不被扩展、反馈幂等及失败重试测试。浏览器验证血常规报告样式、阳性导入并刷新保留、心电图报告及完整反馈。详见 `../output/rehearsal/四项体验完善验收.md`。

连续问诊实测约4.0～5.4秒完成，首段可显示文字约3.4～5.0秒；这是四轮样本，不是速度承诺。此前浏览器也曾出现14秒的波动。详细记录见 `../output/rehearsal/对话提速与浮动流程更新.md`。
