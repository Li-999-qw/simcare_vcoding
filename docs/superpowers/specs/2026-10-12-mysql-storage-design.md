# SimCare MySQL 存储设计

## 目标

将门户、用户、任务、训练记录、七个病例引擎的会话、病例身份资料和可编辑配置统一存入新建的空 MySQL 数据库 `simcare`。保留 PNG、音频模型、教学来源文件等不可变资源在文件系统，数据库保存资源引用。

## 数据边界

- 数据库连接通过未纳入 Git 的本地配置提供，Python 使用 SQLAlchemy + PyMySQL，字符集 `utf8mb4`。
- 用户、任务、病例目录和审计沿用现有 SQLAlchemy 数据模型，迁入 MySQL。
- 门户编辑状态暂以 MySQL JSON 文档保存，并逐步投影到病例目录与任务表。复杂会话状态作为 MySQL JSON 快照，使用病例、会话、阶段和更新时间索引。
- 病例身份、问诊事实和报告描述按病例与语言存为可版本化行。新会话读取数据库内容；历史训练记录保留当时快照。
- 角色模型密钥与语音凭据仍由 Windows DPAPI 加密，密文存入数据库；数据库不保存明文密钥。

## 迁移与兼容

1. 先验证 `simcare` 为空并创建新表，不修改其他数据库。
2. 从 `data/clinical.db`、各引擎 `runtime/sessions.json` 和当前病例源文件导入；目标已有相同主键时跳过并记录。
3. 完成校验后，运行时只从 MySQL 读写业务状态；原文件保留作迁移备份。
4. 前端从 API 的 `registration` 字段显示姓名、性别、年龄、职业，避免再写死病例身份。

## 验收

- 新练习、患者对话、病历、检查报告、门户任务和用户操作重启后仍可从 MySQL 读取。
- 修改数据库病例身份后，新练习在接诊页、场景标题、查体和检查报告中显示一致。
- 中文、英文与维吾尔语病例路由可用；现有历史记录不丢失。
